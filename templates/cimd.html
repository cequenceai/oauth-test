About Client ID Metadata Documents

CIMD (draft-ietf-oauth-client-id-metadata-document) lets an OAuth client identify itself with a URL instead of a pre-registered client ID. The authorization server fetches the URL, reads the JSON metadata document, and treats the client as registered. The MCP specification (2026-07-28) deprecated Dynamic Client Registration in favor of CIMD.

  • The client_id URL must be HTTPS, with a path, and no fragment or userinfo
  • The document's client_id field must exactly string-match the URL
  • Shared-secret auth methods (client_secret_*) are forbidden - use none + PKCE, or private_key_jwt
  • The AS advertises support via client_id_metadata_document_supported: true in its metadata (check the Discovery tool on the DCR tab)
